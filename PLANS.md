# Plan Management & Index

## Overview
All plans are created directly in the `plans/` folder and tracked in this index document. Plans are markdown files with descriptive titles and no YAML frontmatter.

## Workflow

### 1. **Plan Creation**
- Create plan markdown files directly in `plans/` folder
- Use descriptive file names matching the plan title
- Format: markdown, no YAML frontmatter
- Example: `plans/Spec-Driven-Validator-Architecture.md`

### 2. **Review & Approval**
- Share the plan for review and feedback
- Request approval with: **"go ahead"** or explicit "approve"
- Upon approval, the plan is active and tracked below

### 3. **Updates & Iterations**
- If a plan needs updates:
  1. Edit the plan file directly in `plans/` folder
  2. Share the updated version for review
  3. Request **"go ahead"** to proceed with implementation
  4. The updated plan remains in the same file

## Naming Convention
- Use descriptive, hyphenated names reflecting the plan title
- Example: `Spec-Driven-Validator-Architecture.md`, `Data-Model-Design.md`
- One plan per file in `plans/` folder

## Git Configuration
- All files in `plans/` folder are tracked in Git for historical reference
- This keeps all approved decisions documented and versioned
